01 — What was broken

Five defects were already live

These weren't introduced by the redesign. They were found while verifying it, by running the real Worker against your real Notion database rather than trusting that a passing build meant a working site.

fatal
Every post page returned 404
isomorphic-dompurify resolves its Node export on Workers, which pulls in jsdom. There is no DOM in the Workers runtime, so markdownToHtml threw on every post. It surfaced as a generic 500 because the error was being swallowed.
fatal
Homepage crashed on an empty field
The transformer read properties.Description.rich_text[0].plain_text with no guard. One post with a blank description would throw and take down the whole index, not just that row.
wrong
Read time displayed as “NaN mins read”
The code read properties.words; the Notion property had been renamed to Words. Math.ceil(undefined / 200 + 1) is NaN.
wrong
RSS shipped the string “undefined”
Every feed link read undefined/blog/… because PUBLIC_SITE_URL was never set. Now the origin comes from the request itself, so a missing variable cannot produce a broken feed again.
gap
A finished component wired to nothing
Head.svelte existed with canonical, Open Graph, Twitter and RSS tags fully written, and was imported by no page. Every route shipped a bare <title>.

02 — Approach

Cache the finished work, not the API call

The original code called Notion on every request. The obvious fix is to cache the API response — but the expensive part isn't the query, it's everything after it: fetching the blocks, converting to markdown, and running Shiki over the code blocks.

So the cached unit is the rendered HTML, keyed by slug in Cloudflare's edge cache. A hit skips the Notion query, the block fetch, and the syntax highlighting in one step. No KV, no D1, no Redis — the cache API needs no binding and no provisioning.

GET /blog/<slug>
 ├─ edge cache HIT  → html + counts  ≈3ms, 0 Notion calls
 └─ edge cache MISS → notion query → blocks → markdown → shiki → cache put  ≈1.3s, once

Nothing slow sits on the reader's path

A view increments a counter in Notion, but the response returns first and the write finishes in waitUntil — 202 in 4.7ms, measured. Like counts come down inside the cached HTML, so there is no fetch on load. The reader's own vote is read from localStorage, because that is the one piece of state cached HTML can never contain.

The result: opening a post makes zero API calls. It previously made two, one of which hit Notion per reader. That also removes the rate-limit ceiling — Notion allows roughly three requests per second, and reads no longer reach it at all.

Writes correct the cache instead of waiting it out

When someone likes a post, the new count is written through to the cache in the same operation that writes to Notion. The next reader sees the correct number immediately rather than a value known to be stale.

04 — Decisions

Three calls worth recording

Counters — where the data lives

Notion is the store; there is no database. The cost is that increments are read-then-write, so two likes landing in the same second can cost one count. Accepted deliberately: a real counter needs D1 or a Durable Object, and that complexity isn't earned at this traffic.

Vote records live in the edge cache — per-datacenter and evictable, which is the honest use for it. It stops casual double-voting without a database, and the worst failure is that someone can vote again much later. Identity is SHA-256(ip + user-agent + slug), truncated: no cookie, no IP stored.

Social cards — build time vs edge

First attempt rendered them at request time and Cloudflare refused: Wasm code generation disallowed by embedder. Workers won't compile WebAssembly at runtime. I fell back to generating cards during the build, which worked but meant a renamed post kept a stale card until the next deploy.

The second attempt succeeded. adapter-cloudflare doesn't bundle the server code — it copies files and lets wrangler bundle, and wrangler handles wasm natively. Keeping workers-og out of Vite entirely and deferring its import to runtime made it work. Cards now render at the edge, cached after the first request, and are correct the moment a post is renamed.

Sanitizer — replaced, not removed

sanitize-html replaced isomorphic-dompurify. Its allowlist keeps Shiki's spans and inline styles, images, and video embeds; iframes are permitted only from youtube-nocookie.com and player.vimeo.com, so a video in a post works while a link to anywhere else is dropped.

05 — Built

What changed on the surface

Shell

Homepage is now an index: name, a one-line bio, a mono key/value block, then posts as date · title · read time. Descriptions unfold on hover via a grid-template-rows: 0fr → 1fr transition — one animatable property, no height measuring, no JavaScript — and are simply always visible under @media (hover: none), since a phone can never trigger a hover.

Tags filter through the URL (/?tag=github), so a filtered view is shareable, the back button steps through filters, and the chips are real links. One Tag.svelte serves both the homepage filter and the post header.

Post page

The article itself is untouched — same max-w-4xl, same prose prose-lg. Added around it: a back link, title, date and read time, tags, like/dislike, and a next-post link. It previously rendered raw markdown with no heading or metadata at all, and imported the layout component manually, which rendered the header twice.

Motion

The entrance animation was JavaScript — an onMount and afterNavigate pair querying the DOM and setting timeouts. It is now one CSS keyframe with a per-element animation-delay. Elements are visible by default and the keyframe only plays the arrival, so nothing can be stranded invisible. transform and opacity only, 520ms, disabled under prefers-reduced-motion.

Also added

Video embeds (Notion video blocks previously rendered as plain links), lazy images with captions, /about, a styled error page, sitemap.xml, a robots.txt route that emits an absolute sitemap URL, and self-healing slug lookups so a rename no longer produces dead links for thirty minutes.

06 — Open

What still needs you

Two variables. /sync — which clears the cache after a rename — stays disabled until the token exists.

PUBLIC_SITE_URL=https://your-domain
SYNC_TOKEN=<long random string>
REDIS_URL=…   # nothing reads this any more

For production these belong in wrangler secret put, not just .env.
